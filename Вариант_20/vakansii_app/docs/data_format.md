# Структура файла данных `data/jobs.json`

Данные хранятся в одном JSON-файле (SQLite не используется, как требует ТЗ).
Кодировка — UTF-8, отступы — 2 пробела, `ensure_ascii=False`.

```json
{
  "vacancies": [...],
  "notes": [...],
  "reminders": [...],
  "next_id": {"vacancies": 5, "notes": 4, "reminders": 3}
}
```

## Вакансия (`vacancies`)

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `id` | INTEGER | да | уникальный идентификатор |
| `company` | TEXT | нет | название компании |
| `position` | TEXT | **да** | должность |
| `salary` | TEXT | нет | вилка зарплаты |
| `status` | TEXT | да | один из: «Отклик», «Тестовое», «Собеседование», «Оффер», «Отказ» |
| `source` | TEXT | нет | источник вакансии (hh.ru, LinkedIn и т. п.) |
| `link` | TEXT | нет | ссылка на вакансию |
| `response_date` | TEXT (DATE) | да | дата отклика, формат `ГГГГ-ММ-ДД` |

## Заметка (`notes`)

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `id` | INTEGER | да | уникальный идентификатор |
| `vacancy_id` | INTEGER | да | ссылка на вакансию |
| `date` | TEXT (DATE) | да | дата заметки, формат `ГГГГ-ММ-ДД` |
| `text` | TEXT | да | текст заметки по этапу отбора |

## Напоминание (`reminders`)

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `id` | INTEGER | да | уникальный идентификатор |
| `vacancy_id` | INTEGER | да | ссылка на вакансию |
| `date` | TEXT (DATE) | да | дата события (собеседование, дедлайн) |
| `event` | TEXT | да | описание события |

## Счётчик `next_id`

Хранит следующий свободный идентификатор для каждой сущности, чтобы id не
переиспользовались после удаления записей.

## Резервное копирование и целостность

* **Атомарная запись.** Каждый раз при сохранении сначала пишется временный
  файл `jobs.json.tmp`, затем он атомарно заменяет основной файл
  (`os.replace`). Обрыв питания/сбоя не оставляет «полузаписанный» файл.
* **Резервные копии.** После каждой успешной записи текущее состояние
  копируется в `data/backups/jobs_ГГГГММДД_ЧЧММСС_мкс.json`; хранятся
  последние **5** копий, старые удаляются автоматически.
* **Валидация при загрузке.** Проверяются типы, обязательные поля, статус
  и формат дат. Если основной файл повреждён (битый JSON, неверная
  структура), приложение поочерёдно пытается загрузить резервные копии от
  самой свежей; успешная копия восстанавливается поверх основного файла.
  Если ни одна копия не читается — создаётся пустая база, приложение не
  аварийно завершается.
