# Техническое описание: архитектура и взаимодействие модулей

## Слои

```
┌─────────────────────────────────────────────┐
│ UI-слой (main.py + ui/*.ui)                 │
│ QMainWindow/QDialog, загруженные через      │
│ PyQt6.uic.loadUi (динамическая загрузка)    │
└──────────────┬──────────────────────────────┘
               │ form_data() / методы ApplicationLogic
┌──────────────▼──────────────────────────────┐
│ Логика (app/logic.py, ApplicationLogic)     │
│ валидация форм, статистика, напоминания,    │
│ экспорт                                     │
└──────────────┬──────────────────────────────┘
               │ CRUD
┌──────────────▼──────────────────────────────┐
│ Данные (app/data_access.py,                 │
│ DataAccessLayer) — JSON, атомарная запись,  │
│ резервные копии, валидация и восстановление │
└─────────────────────────────────────────────┘
```

UI-слой не обращается к файлам напрямую; слой данных не знает про Qt.
Это позволяет тестировать логику и хранилище без графического интерфейса
(см. `tests/test_logic.py`).

## Динамическая загрузка интерфейса

Каждое окно наследуется от соответствующего класса Qt и в `__init__`
вызывает `load_ui(self, "имя.ui")` — обёртку над `PyQt6.uic.loadUi(path, self)`.
Qt Creator открывает файлы `ui/*.ui` напрямую, а правки дизайна не требуют
перекомпиляции. Виджеты адресуются по `objectName` (например,
`self.tableJobs`, `self.btnExport`), заданному в Qt Designer.

## Поток данных

1. Пользователь меняет данные в форме → `JobDialog.form_data()` собирает
   словарь.
2. `ApplicationLogic.validate_vacancy_form()` проверяет поля (позиция не
   пустая, статус из справочника, корректные даты) — ошибки возвращаются как
   `ValidationError` с понятным текстом.
3. `ApplicationLogic` вызывает CRUD-методы `DataAccessLayer`; тот изменяет
   структуру в памяти и вызывает `save()`.
4. `save()`: атомарная запись во временный файл → `os.replace` → резервная
   копия → обрезка до 5 копий.
5. После каждого изменения главное окно перечитывает данные и обновляет
   таблицу, панель напоминаний и заметок (`refresh_jobs`).

## Напоминания

Панель напоминаний строится методом `ApplicationLogic.reminders_panel()`:
события делятся на «Просрочено», «Скоро» (≤ 14 дней) и «Планируется»,
сортируются в этом порядке, затем по дате. В строку подставляется компания
и позиция связанной вакансии.

## Статистика и экспорт

* `status_counts()` — счётчики по всем статусам за всё время;
* `period_statistics(from, to)` — счётчики по датам откликов в диапазоне;
* `export(path, fmt, ...)` — CSV (разделитель «;», UTF-8 с BOM для Excel)
  или JSON; блоки вакансий и статистики включаются независимо.

## Обработка ошибок

* Формы: валидация до записи, диалог с понятным сообщением, окно не закрывается.
* Файл данных: восстановление из резервных копий при повреждении; при полном
  отсутствии читаемых данных — старт с пустой базы.
* Файловая система: ошибки записи CSV/JSON показываются, приложение продолжает
  работу.
* Глобальный `sys.excepthook`: любая непойманная ошибка выводится в
  информационное окно, а не приводит к «тихому» падению.
* Каскадное удаление: вместе с вакансией удаляются её заметки и напоминания.
